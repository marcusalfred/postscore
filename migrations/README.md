# Database Migrations

This directory contains Alembic migrations for managing database schema changes in the Postscore application.

## UUID to ULID Migration

The codebase has been transitioned from using UUIDs to ULIDs for all primary and foreign keys. ULIDs (Universally Unique Lexicographically Sortable Identifiers) provide several advantages over UUIDs:

1. They are sortable by creation time (first 10 characters are time-based)
2. They are more compact and URL-friendly (26 characters vs 36 for UUID)
3. They maintain compatibility with UUID-based systems while offering improved performance

### Applying the Migration

The migration has been prepared in two ways:

1. **Using Alembic (requires database connection):**
   ```bash
   alembic upgrade head
   ```

2. **Manual SQL Execution (for situations where direct database access is available):**
   A SQL script has been generated at `migrations/uuid_to_ulid_migration.sql`. This can be executed directly against the database:
   ```bash
   psql -U your_username -d your_database -f migrations/uuid_to_ulid_migration.sql
   ```

### Migration Details

The migration performs the following operations:

1. Creates a PostgreSQL function to convert UUIDs to deterministic ULID-like values
2. Temporarily drops foreign key constraints
3. Updates all primary keys and foreign keys to ULID format
4. Re-adds all constraints
5. Cleans up temporary objects

### Important Notes

- This migration is **not reversible** as the mapping from UUIDs to ULIDs is one-way
- All tables using TEXT columns for IDs will maintain compatibility with the new ULID format
- This migration does not change any application code; that has been updated separately
- All new entries will use true ULIDs generated by the application code
