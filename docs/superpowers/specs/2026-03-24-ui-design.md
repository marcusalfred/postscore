# POSTscore UI — Design Spec

**Date:** 2026-03-24
**Status:** Reviewed

---

## Overview

POSTscore is a golf score tracking API. This spec covers a mobile-first UI that lets a friend group record rounds in real time and review scores, stats, and standings after play.

---

## Users & Context

- **Audience:** Small friend group (not a public platform)
- **Primary context:** On the course — recording scores hole by hole while playing
- **Secondary context:** Post-round — reviewing stats, comparing with friends
- **Devices:** iOS and Android phones (primary), web browser (secondary)

---

## Platform

**Expo (React Native + web)** — single TypeScript codebase targeting iOS, Android, and web via Expo Router.

**Why Expo over a web-only PWA:** The live scorecard is the most important screen. Native touch targets, no browser chrome, and offline resilience are worth the added setup for a group that will install it on their phones.

### Dependencies

| Package | Purpose |
|---|---|
| `expo` + `expo-router` | Navigation and native runtime |
| `react-native` | UI primitives |
| `nativewind` | Tailwind CSS for React Native (styling) |
| `@tanstack/react-query` | API state, caching |
| `@react-native-async-storage/async-storage` | Persist in-progress round and theme preference |
| `@react-native-community/netinfo` | Detect reconnect to flush offline queue |
| `expo-secure-store` | Store JWT token securely |

## Visual System

**Monochrome base** — no brand colour in UI chrome:

| Role | Light | Dark |
|---|---|---|
| Background | `#f5f5f5` | `#111111` |
| Surface (cards) | `#ffffff` | `#1c1c1e` |
| Elevated surface | `#f0f0f0` | `#2a2a2a` |
| Primary text | `#111111` | `#ffffff` |
| Secondary text | `#888888` | `#666666` |
| Muted text | `#bbbbbb` | `#444444` |
| Border | `#e5e5e5` | `#2a2a2a` |
| Primary action (buttons) | `#111111` bg / `#fff` text | `#ffffff` bg / `#111` text |

**Scoring accents** — the only colour in the app:

| Score vs par | Colour |
|---|---|
| Under par (birdie, eagle) | `#43a047` green |
| Over par (bogey, double+) | `#e53935` red |
| Even par | Neutral (no accent) |

Accents appear on: running to-par display, hole progress dots, round history cards, leaderboard standings.

**Dark mode:** User preference stored in AsyncStorage. `Appearance.colorScheme` used on first launch. Toggleable in Profile settings.

**Typography:** System font (`-apple-system` / `Roboto`). Bold weights (`700`, `800`) for scores and key numbers. `600` for labels. Regular for body.

## Navigation

Three bottom tabs, always visible:

| Tab | Icon | Content |
|---|---|---|
| Play | ⛳ | Scorecard when round active; Start Round form when idle |
| Rounds | 📋 | Personal round history |
| Friends | 👥 | Friend group leaderboard |

The Play tab is the default tab. No hamburger menu, no drawer.

Auth screens (`/login`, `/signup`) sit outside the tab layout. The root layout redirects unauthenticated users to `/login`.

**Profile** (`/profile`) is not a tab — it is reached via a settings icon (⚙) in the top-right corner of the Friends tab header.

Round Summary is accessible two ways:
- After finishing a round (Play tab pushes to `rounds/[id]`)
- Tapping a card in the Rounds tab (pushes to `rounds/[id]` from within the Rounds stack)

## Screens

### 1. Login
- Email + password fields
- "Log in" primary button → `POST /api/v1/auth/login`
- **Important:** This endpoint uses `application/x-www-form-urlencoded`, not JSON. The field names are `username` (email) and `password`. `lib/api.ts` must handle this as a special case.
- JWT stored in SecureStore on success
- Link to Signup

### 2. Signup
- Name, email, zip, password fields
- "Create account" button → `POST /api/v1/auth/signup` (JSON body)
- Response is `SignupResponse: { player, access_token, token_type }` — token is available immediately, no second login call needed
- JWT stored in SecureStore; navigate to Play tab

**Empty state:** First-time user lands on the Start Round screen with no history — no special empty state needed here.

### 3. Play — Start Round (no active round)
- Course picker (searchable, from `GET /api/v1/courses/`) — public endpoint, no auth required. Course names are cached in TanStack Query (`staleTime: Infinity`) for use throughout the session (rounds list, scorecard header).
- Tee box selector (pill buttons, populated from selected course's `tees` array). Note: the tee box identifier is `tee_id` on objects in the `CourseResponse.tees` array — this value maps to `tee_box_id` in the `POST /api/v1/rounds/` request body.
- **On tee box selection:** Fetch `GET /api/v1/courses/tee-boxes/{tee_box_id}` to retrieve `TeeBoxDetailResponse` containing the full list of `TeeBoxHoleResponse` objects with their IDs. These hole IDs are required to submit scores. Cache this response alongside the round state in AsyncStorage.
- Holes selector: 9 or 18 (pill buttons, default 18)
- "Start Round" button → `POST /api/v1/rounds/`
- Active round state persisted to AsyncStorage — see Offline Resilience section for the full schema.

**Empty state:** If no courses exist, show "No courses available" with a note to add courses via the API.

### 4. Play — Live Scorecard (round active)
**Header:** Course name (from cache), tee name, running to-par (coloured accent), "thru N" holes played.

**Hole progress row:** One dot per hole. Filled with scoring colour for completed holes; outlined ring for current hole; empty circles for upcoming holes.

**Current hole panel:**
- Hole number, par, yards (from tee box hole data — field name is `yards` in `TeeBoxHoleResponse`)
- Score stepper (− / score circle / +). Circle border uses scoring colour once score differs from par. Default score = par.
- Par label below score: `EAGLE`, `BIRDIE`, `PAR`, `BOGEY`, `DOUBLE`, `+N` for worse.
- GIR toggle (YES / NO). Shown on all holes.
- Fairway toggle: HIT / LEFT / RIGHT / SHORT / LONG — hidden on par-3s (par-3s have no fairway). These display labels map to API values: `HIT → 'o'`, `LEFT → '<'`, `RIGHT → '>'`, `SHORT → 'v'`, `LONG → '^'`.
- Putts stepper (0–6, default 2).

**"Next Hole →" button** → `POST /api/v1/rounds/holes`. On hole 18 (or 9 for a 9-hole round), becomes "Finish Round" → `PATCH /api/v1/rounds/{id}` with `end_time: new Date().toISOString()`. Send only `end_time` — `total_score` is maintained automatically by the API as holes are submitted and must not be sent at finish (the `RoundPatchRequest` schema accepts `total_score` but the client should not compute or send it).

**Offline handling:** See Offline Resilience section.

**Abandon Round:** Accessible via a `•••` menu in the header. Prompts confirmation. Clears AsyncStorage active round state. Does not call any API endpoint (round remains in backend as incomplete).

**Error state:** If hole submission fails and offline queue is unavailable, show a non-blocking toast. Never block the user from advancing to the next hole.

### 5. Round Summary (`rounds/[id]`)
- Full 18-hole grid: hole number, par, score, to-par per hole with colour accents
- Stats row: Total Score, To-Par, GIR %, FIR %, Avg Putts, Penalties
- Data from `GET /api/v1/rounds/{id}` (`round_holes` array) and `GET /api/v1/rounds/{id}/stats`
- "Done" navigates to Rounds history tab

**Loading state:** Skeleton cards while fetching.

**Error state:** "Could not load round stats" with retry button.

### 6. Rounds (history tab)
- Flat list of past rounds, newest first, from `GET /api/v1/rounds/?player_id={currentPlayerId}`
- Each card (`RoundCard`): course name (from cache), date, tee, holes, total score, to-par (coloured). Note: `GET /api/v1/rounds/` does not return per-round stats (GIR, FIR, putts) — those fields are only available via `GET /api/v1/rounds/{id}/stats`. To avoid N+1 fetches, the history list shows only the fields available in `RoundResponse`.
- Tap → navigate to `rounds/[id]` (Round Summary)

**Empty state:** "No rounds yet. Head to the Play tab to start your first round."

**Loading state:** Skeleton list.

### 7. Friends (leaderboard tab)

**Data fetching (two-step):**
1. `GET /api/v1/players/` — fetch all players in the system (all are treated as "friends")
2. For each player: `GET /api/v1/rounds/?player_id={id}` — fetch their rounds in parallel
3. Client-side aggregation: compute avg score over last 5 rounds per player, sort ascending

**Display:** Ranked list. Each row: rank, avatar (initials), name, rounds played, avg score, avg to-par (coloured).

**Loading state:** Show skeleton rows while parallel requests complete. Partial failures (one player's rounds failing to load) are silently skipped — that player is omitted from the leaderboard rather than blocking the whole view.

**Empty state (no other players):** "Invite friends to join and their scores will appear here."

### 8. Profile
- Accessed via a settings icon (⚙) in the top-right corner of the Friends tab header
- Displays name, email, handicap — loaded from `GET /api/v1/auth/me`
- Dark mode toggle: System / Light / Dark (stored in AsyncStorage)
- Edit name/handicap → `PATCH /api/v1/players/{id}`
- Logout — clears SecureStore token and AsyncStorage, redirects to Login

## API Integration

Base URL configured via `EXPO_PUBLIC_API_URL` environment variable (defaults to `http://localhost:8000`).

**Auth:** JWT Bearer token read from SecureStore, attached as `Authorization: Bearer <token>` on every request except login, signup, and `GET /api/v1/courses/` (which is public).

**Content-type note:** All endpoints accept and return JSON **except** `POST /api/v1/auth/login`, which requires `application/x-www-form-urlencoded` with fields `username` and `password`.

**Key endpoints used:**

| Screen | Endpoint |
|---|---|
| Login | `POST /api/v1/auth/login` (form-encoded) |
| Signup | `POST /api/v1/auth/signup` (JSON) → returns `{ player, access_token }` |
| Current user / Profile load | `GET /api/v1/auth/me` |
| Course list (+ cache for names) | `GET /api/v1/courses/` (public — no auth required) |
| Tee box holes (IDs for scoring) | `GET /api/v1/courses/tee-boxes/{tee_box_id}` (requires auth) |
| Start round | `POST /api/v1/rounds/` |
| Score a hole | `POST /api/v1/rounds/holes` |
| Finish round | `PATCH /api/v1/rounds/{id}` (`end_time` only) |
| Round with holes | `GET /api/v1/rounds/{id}` |
| Round stats | `GET /api/v1/rounds/{id}/stats` |
| Round history | `GET /api/v1/rounds/?player_id={id}` |
| All players (leaderboard) | `GET /api/v1/players/` |
| Edit profile | `PATCH /api/v1/players/{id}` |

**Course name resolution:** `GET /api/v1/courses/` is fetched once at session start and held in TanStack Query cache (`staleTime: Infinity`). Round cards and scorecard headers look up course/tee names from this cache using `course_id` and `tee_box_id`. Note: the course list does not include per-hole data or hole IDs — those require a separate call to `GET /api/v1/courses/tee-boxes/{tee_box_id}` when starting a round.

## Offline Resilience

An in-progress round is always recoverable:

1. **On "Start Round":** Write `{ round_id, course_id, tee_box_id, tee_box_holes: [{ id, number, par, yards }], holes_total, scored_holes: [] }` to AsyncStorage. `tee_box_holes` is populated from the `TeeBoxDetailResponse.holes` array returned by `GET /api/v1/courses/tee-boxes/{tee_box_id}` (fetched during tee box selection). Note: the per-hole yardage field in `TeeBoxHoleResponse` is `yards`, not `yardage`. Hole `id` values are required to submit scores.
2. **On each "Next Hole":** Append hole data to `scored_holes` in AsyncStorage, then attempt `POST /api/v1/rounds/holes`. On failure, push to a separate `offline_queue[]` array in AsyncStorage.
3. **On reconnect:** `NetInfo.addEventListener` fires when connectivity is restored. A queue processor reads `offline_queue`, submits each item in order, removes successfully synced items.
4. **On app reopen mid-round:** Root layout reads AsyncStorage for an active `round_id`. If found, restores the scorecard at the correct hole.
5. **On "Finish Round":** Flush queue before sending the PATCH, or queue the PATCH itself if still offline.

## Out of Scope (v1)

- Friend request / invite system (all system users visible as "friends")
- Push notifications
- Course creation from the UI (use the API directly or seed data)
- Handicap calculation
- Multi-player live scoring in the same session
- App Store / Play Store submission (Expo Go for the friend group)
